## File-tool coverage map

Initialize writes only inside the configured workspace. Render/render-design-system, sync-status/preview/apply/resume/trash/restore and prepare/present use validated project IDs and the same DesignWorkspace recovery/registry paths. Find-component reads that registry. Register-asset adds the bounded asset resolver. Export-asset/export-design-package use the separate private export directory writer. Reader, validation, connection and performance tools have no caller-selected filesystem destination. Direct Figma commands cannot execute filesystem or shell operations.

The trusted local workspace must not be concurrently renamed by a malicious same-user process. O_NOFOLLOW protects final entries and canonical checks reject known symlinks, but path-based directory checks are not an openat-style defense against every time-of-check/time-of-use ancestor swap. Any process able to read the user's private token is inside the same local-user trust boundary. No remote untrusted multi-user server mode is claimed.

## Dependency remediation

Initial `pnpm audit --json` exited 1: three moderate and two critical advisory entries in Vitest 3.2.7/@vitest/mocker/tinypool. The two critical entries were for tinypool 1.1.1; they are not claims of two independent exploitable paths in Magic UI.

Vitest was upgraded to **4.1.12**, a patched release for the [mocker injection advisory](https://github.com/advisories/GHSA-qxg6-89mg-rqv8). The lockfile no longer includes tinypool, removing the dependency affected by [the tinypool advisory](https://github.com/advisories/GHSA-85c8-ppgw-ccpr). No runtime feature dependency was added. Full tests and clean installation validate compatibility; original audit evidence is preserved.

Final audit exited 0: **0 info, low, moderate, high or critical advisories**. Registry advisory data is a point-in-time result, not a guarantee against unknown vulnerabilities.
